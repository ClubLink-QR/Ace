# 店舗管理アプリ セットアップ

## 同期には「置き場所」が必要です

別々の端末がデータを共有するには、間に必ずサーバー（置き場所）が要ります。
ブラウザ同士が直接やり取りする方法は存在しないため、これは避けられません。

ただし選択肢は2つあり、**同じWi-Fiで使うなら方法1が圧倒的に簡単**です。

|  | 方法1：店内のPC | 方法2：Cloudflare |
|---|---|---|
| アカウント登録 | **不要** | 必要（無料） |
| インストール | Node.js を1回だけ | 不要 |
| インターネット | **不要** | 必要 |
| データの置き場所 | **店内のPC（外に出ない）** | Cloudflare社のサーバー |
| 使用中にすること | PCを起動しておく | なし |
| 費用 | 無料 | 無料 |

---

## 方法1：店内のPCで動かす（同じWi-Fiならこちら）

### 用意するもの

- 店に置くPC 1台（Windows / Mac、中古ノートでも十分）
- 次の4ファイルを**同じフォルダ**に入れる
  - `store-manager.html`
  - `sync-server.js`
  - `起動-Windows.bat`（Windowsの場合）
  - `起動-Mac.command`（Macの場合）

### 初回だけ：Node.js を入れる

1. https://nodejs.org/ を開く
2. 「LTS」と書かれたボタンをダウンロード
3. ダウンロードしたファイルを開いて、「次へ」を押していくだけ
4. Windowsの場合はPCを再起動

### 毎回：起動する

**`起動-Windows.bat`（Macなら `起動-Mac.command`）をダブルクリックするだけです。**

黒い画面が出て、こう表示されます。

```
  タブレットで開く場合（同じWi-Fiに繋いでください）:
    http://192.168.1.20:8787
```

Macで「開発元が未確認」と出たら、ファイルを右クリック →「開く」→「開く」。

### タブレット側

各タブレットのブラウザで、**表示されたURLを開くだけ**です。
同期の設定は自動で入るので、設定画面を触る必要はありません。

ホーム画面に追加しておくと、アプリのように起動できます。

### 注意点

- 黒い画面を閉じるとサーバーが止まります。営業中は開いたままにしてください
- PCとタブレットが同じWi-Fiに繋がっている必要があります
- PCのIPアドレスは再起動で変わることがあります。変わったら新しいURLを開き直すか、
  ルーターの設定でPCのIPを固定してください
- データは `store-data.json` に保存されます。このファイルをコピーすればバックアップになります

## 方法2：Cloudflare Workers（外出先からも見たい場合）

PCを置きたくない、店の外からも売上を見たい、という場合はこちら。
インストール作業はなく、ブラウザ操作だけで完了します。

手順は `cloudflare-worker.js` の冒頭コメントに詳しく書いてあります。

最後に、各タブレットで
**設定 →「連携とデータ」→「他の端末と同期するURL」** に
`https://〇〇〇.workers.dev/sync` を入力し、
**「接続テスト」**を押して「✓ 接続できました」が出れば完了です。

この場合 `store-manager.html` は各タブレットに配るか、
Netlify・GitHub Pages などに置いてください。

---

## うまく同期しないとき

設定 →「連携とデータ」→「接続テスト」を押してください。
失敗の理由が具体的に表示されます。

| 表示 | 対処 |
|---|---|
| 接続できません | URLの綴りを確認。方法1ならサーバーの黒い画面が開いているか確認 |
| サーバーが 404 を返しました | URLの末尾に `/sync` が付いているか確認 |
| サーバーが 500 を返しました | Cloudflareの手順5（KV namespace の追加）をやり直す |
| サーバーが 401 を返しました | URLの `?key=` が合言葉と一致しているか確認 |

---

## 同期のしくみと制限

- 各端末が数秒おきにサーバーへ問い合わせ、最新の状態を取り込みます
- 状態を変えた端末が、その内容をサーバーへ送ります
- **後から送られたものが優先されます（後勝ち）**

まったく同時に別々の端末が同じ卓を操作すると、片方の変更が消える可能性があります。
卓ごとに担当が分かれていれば実用上は問題ありませんが、
会計処理は1台に集約する運用をおすすめします。

## 権限とPIN（初期値）

| PIN | 権限 | 見られる画面 |
|---|---|---|
| 1111 | 注文専用 | 注文端末（卓固定） |
| 2222 | ホール | テーブル・注文・初回・伝票・売上 |
| 3333 | 厨房 | 厨房・在庫 |
| 9999 | 管理者 | テーブル・初回・伝票・厨房・売上・設定 |

**運用前に必ずPINを変更してください**（設定 → アカウントと権限）。
ログイン画面に出ているPIN一覧も、運用時は消してください
（`viewLogin` 関数の `login-hint` の部分）。

## 注文端末の卓番設定

各タブレットの注文画面 右上の歯車 → 管理者PIN → 卓番を選択。
端末ごとに保持されます。
